10. Diagrama de Componentes

El diagrama de componentes UML muestra la organización y dependencias entre los módulos lógicos del sistema. Cada componente encapsula un conjunto de funcionalidades relacionadas y expone interfaces para comunicarse con otros.

Componentes del SIA-NP

El sistema se divide en 8 componentes lógicos, organizados según los casos de uso:

ComponenteCUDescripciónInterfaces
GestionMovimientos CU1, CU4 Registra entradas, salidas, ajustes y devoluciones de mercancía IMovimientos
GestionInventario CU2, CU3 Control de existencias, conteos físicos y kardex IInventario
GestionOrdenes CU5, CU6 Órdenes de compra y recepción de mercancía IOrdenes
GestionProveedores CU5 Catálogo de proveedores IProveedores
GestionProductos CU2 Catálogo de productos y ubicaciones IProductos, IUbicaciones
GestionReportes CU7, CU8 Dashboard ejecutivo y reportes operativos IReportes, IDashboard
GestionUsuarios — Autenticación, roles y bitácora de auditoría IAutenticacion, IBitacora
BaseDeDatos — Persistencia en SQL Server IPersistencia

Diagrama

Notación UML 2.x

  • Componente: rectángulo con estereotipo «component» e icono (dos rectángulos pequeños)
  • Interfaz proporcionada: círculo (lollipop) conectado al componente que la ofrece
  • Interfaz requerida: semicírculo que se conecta a la interfaz proporcionada de otro componente
  • Dependencia: flecha punteada del componente que depende hacia el que provee

Dependencias principales

  • Todos los componentes dependen de BaseDeDatos mediante IPersistencia
  • GestionMovimientos → GestionProductos, GestionInventario
  • GestionOrdenes → GestionProveedores, GestionProductos, GestionInventario
  • GestionReportes → GestionInventario, GestionMovimientos
Relación con el diagrama de clases: cada componente agrupa las clases de entidad, control e interfaz que implementan sus casos de uso. Por ejemplo, GestionMovimientos contiene las clases Movimiento, Entrada, Salida, Ajuste, Devolucion, ControladorMovimientos e InterfazRegistroMovimientos.
